# 프론트엔드 구현·검증 보고서

## 결과 — 2026-09-20

원본 목표 `00-frontend-objective.md` A~H의 관리 프론트엔드를 구현하고 요구사항별 감사를 진행했다. 기존 회원·프로필·운동 API를 유지하고 신규 업무는 SQLite 및 Supabase API에 연결했다. staging 마이그레이션·Edge 적용과 실제 Auth/업무 RPC·센터 격리를 검증했다. 사용자 별도 승인 후 기존 개발 DB를 백업하고 schema 3으로 전환·재시작했다. PG 결제·알림은 범위 밖이다. 기존 사용자 DB·녹화 삭제, 커밋·푸시·운영 배포는 하지 않았다. staging에는 합성 검증 자료만 추가했다. 이전의 포괄적인 완료 표현 대신 아래 검증 범위와 미검증 환경을 함께 적용한다.

## 실행 환경과 미리보기

루트에서 Python 3.12+, Node 22+(npm 포함), Chrome을 사용한다.

```powershell
powershell -ExecutionPolicy Bypass -File box/tools/dev.ps1 -Action setup
powershell -ExecutionPolicy Bypass -File box/tools/dev.ps1 -Action test
powershell -ExecutionPolicy Bypass -File box/tools/dev.ps1 -Action serve
```

npm이 PATH에 없으면 setup/test에 `-NodeDirectory .tools/node-v22.20.0-win-x64`를 지정한다. 현재 기기에 이 portable Node와 Python 3.12.14 가상환경을 준비했다. 기존 가상환경이 오래됐으면 setup에 `-Python`과 Python 3.12 이상 실행 파일 경로를 지정하면 업그레이드한다. 개인 런타임 경로는 소스에 저장하지 않았다. 의존성은 npm lockfile로 기록했다.

기존 v0/v1/v2 DB는 현재 schema 3 소스에서 자동 업그레이드하지 않는다. 현재 admin 계정이 있는 DB는 사용자 별도 승인 후 백업/전환했으며 기존 계정과 비밀번호를 보존했다. serve는 loopback과 `artifacts/development-db.txt`에 기록된 DB를 사용하며 파일이 없을 때만 `artifacts/development.db`를 기본값으로 사용한다. 기존 `backend/boxing_coach.db`를 열거나 마이그레이션하지 않는다. 새 DB에는 기본 계정이 없다. 테스트는 별도 임시 DB를 사용하고 readiness가 반환한 실제 worker PID를 종료한 뒤 정리한다. Windows 가상환경 런처 PID만 종료하여 DB 잠금이 남던 테스트 정리 문제를 수정했다.

- `/preview.html`은 기본 OFF. `/preview.html?enable=1`로 명시적으로 활성화한다.
- 고정 표시하는 “개발용 샘플 데이터” 배너, 관리자/코치/회원 역할 선택, 기준일(기본 2026-09-18)을 제공한다.
- 전용 localStorage 키 `boxingcoach.dev.operations.v1`만 사용한다. 기존 인증·회원·직원·설정·녹화를 읽거나 변경하지 않으며 API 호출도 하지 않는다.
- “샘플 초기화”는 전용 키만 제거한다. 이전 샘플에 새 운동 기록이 없으면 초기화로 최신 시나리오를 확인한다.
- “다음 요청 실패 재현” 후 저장이나 기준일 변경으로 저장/조회 오류를 확인한다.
- 손상 저장소는 덮어쓰지 않는다. 이전 v1의 센터/본인 프로필 누락은 메모리에서 합성 기본값으로 보완하며 기존 목록은 보존한다.
- 신규 회원 프로필은 UNCONNECTED이며 로그인 계정 생성을 가장하지 않는다. 모션 점수·AI 피드백·가짜 녹화를 생성하지 않는다.

직원 재직 상태·로그인 계정 상태·회원권 상태를 구분한다. 직원 생성이나 본인 프로필 수정은 로그인 권한을 바꾸지 않는다. 개발용 관리자만 상품·수납·센터·직원을 변경하고 코치는 기존 회원 수정·회원권·출석·메모를 변경한다. 회원 생성·삭제는 센터 소유자만 수행한다. 회원은 본인 프로필·운동 삭제만 변경 가능하며 다른 회원·상담 메모·직원 목록을 받지 않는다. 플랫폼 관리자의 기존 실제 조회는 유지하고 회원 수정·운동 삭제 버튼을 숨긴다. UI는 서버 보안 경계를 대신하지 않는다.

운동 삭제는 기존 API 성공 후 장치 녹화를 지운다. 장치 삭제 실패 시 같은 모달에서 장치 삭제만 재시도한다. 실행 중 세션은 종료 전 삭제를 막는다. 테스트에서만 합성 기록과 녹화를 삭제했다.

대형 shell에서 화면 렌더링을 분리했다. 필터는 제출 시에만 다시 그려 입력 중 포커스를 보존한다. 회원 상세 탭에 tab/panel 연결, roving tabindex, 좌우·Home·End를 제공한다. dialog는 포커스를 가두고 저장 후 DOM이 교체돼도 원래 버튼으로 복귀한다. 저장 중 중복 제출·Escape 닫기를 차단하며 실패 입력을 보존한다. 저장 후 목록 조회 실패를 별도 안내하여 재생성을 유도하지 않는다. 계정 생성 후 조회 실패도 생성 폼을 닫고 새로고침을 제공한다.

설정 프로필 모달도 공통화하고 폐기 modal CSS 52줄·미사용 상태/도우미/기록 선택 핸들러를 제거했다. 기존 세션 디자인은 변경하지 않았다. 모바일 표는 가로 스크롤한다. 웹 0.7.0, PWA 캐시 `boxingcoach-shell-2026-09-20-1`에 새 모듈을 등록했다. Android assets의 web 연결과 Windows worker web 번들 구조는 유지한다.

## 이전 프론트 단계 재감사 기록

아래 80개/10개 회귀 기록은 이전 단계 당시의 근거다. 이후 업무 API·화면을 변경했으며 최신 검증과 적용 제약은 [06](06-operations-integration.md)에 정리했다.

### 확인한 결함과 근거

최종 전체 회귀는 루트에서 `powershell -ExecutionPolicy Bypass -File box/tools/dev.ps1 -Action test -NodeDirectory .tools/node-v22.20.0-win-x64`로 실행하여 종료 코드 0을 확인했다. Python 80개, 스크립트에 등록된 JS 10개 테스트 파일, PostgreSQL 역할 검증을 포함한다. 이후 빈 녹화의 종료 실패→명시적 재시도에서 세션 상태·카메라 해제·실패 안내를 확인하는 단위 검사를 보강하고 `node tests/test_session_media.js`를 다시 통과했다. 이후 제품 코드는 변경하지 않았다.

진단 시 Chrome 153.0.8010.50의 합성 스트림이 `ended`가 되면 isTypeSupported=true인 MP4/WebM에서도 즉시 stop 또는 NotSupportedError가 발생했다. 이는 코덱 지원 플래그만으로 실제 녹화 가능성을 보장할 수 없음을 보여준다. 샌드박스 밖 기본 회귀는 통과했지만 별도 다중 코덱 프로브에서도 트랙 종료를 관찰했으므로, 원인을 특정 코덱이나 샌드박스만으로 단정하지 않는다. 확인된 제품 결함 두 가지(불필요한 재개방, 중단 데이터 폐기)는 수정했고 실제 단절도 안전하게 처리한다. OS/드라이버의 실제 장치 고장 원인을 진단했다는 의미는 아니다.

`test_operations_states_browser.js`는 회원 57건 및 회원권/출석/수납/운동/직원 각 47건의 긴 목록, 모바일 페이지 넘침·페이지 이동·검색 없음·빈 상태를 확인한다. 센터·직원·본인 프로필을 포함해 로딩/조회 실패/재시도를 검사한다. 단일 센터/본인 프로필은 목록이 아니므로 빈 목록 대신 필수 객체 계약·조회 오류 상태로 검증한다. 새로운 업무 변경은 모두 공통 dialog의 저장 중 상태·실패 입력 보존을 사용하며 각 폼에서 실패 후 저장을 재현했다.

실제 WebView2/Android 장치·카메라 하드웨어는 미검증이다. Supabase staging의 실제 Auth·Edge·업무 RPC 검증은 완료했으며 배포된 중앙 웹의 종단 검증과 구분한다. 원본 목표의 “실행하지 못한 환경은 미검증으로 남긴다”에 따라 명시하며 브라우저와 컴파일 검증을 실제 장치 검증으로 대체하지 않는다. 새 업무 API 구현·계약은 [05 명세](05-frontend-api-contract.md), 전환·검증 결과는 [06](06-operations-integration.md)에 기록했다. 챗봇·중앙관제·서버·기록 앱 확장은 이번 범위 밖이다.

## 관리 UI 추가 정리

최종 Python 회귀 101개와 git diff --check 통과. 개발 DB의 백업·전환·기존 관리자 로그인도 확인했다.

운동 세션 외 반복 설명을 정리하고 회원 수정/삭제 버튼, 메모·신체 정보·선택 이용권 만료일, 주말 달력 색상과 오늘 전환을 연결했다. 링/샌드백 UI는 제거하고 라운드 분/초를 한 줄로 배치했다. 센터 공통 연락처·주소·운영시간은 서버에, 라운드는 장치에 저장한다. 설정과 센터의 폭, 표 세로 정렬을 정리했다. 숨긴 회원권 상태는 원본을 유지하고 배지만 ‘—’로 표시한다. 새 결제 수단은 수납 사실 기록이다. 상세 정책과 검증 범위는 05~06을 따른다.
