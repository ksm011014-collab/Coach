# 프론트엔드 작업 기록

## 진행 상태 — 2026-09-18

**진행 중. 프론트 전체 완료 보고서가 아니다.** 실제 회원·운동 API 통합 및 임의 운영 데이터 제거를 마쳤다. 미리보기의 직원·센터·프로필 흐름 보강, 화면별 상태·접근성 검증, 공통 코드 추가 분리와 최종 완료 감사가 남아 있다. 서버 API·DB 테이블·결제 서비스는 추가하지 않았다.

## 시작 조사와 기준 검증

- 루트 `AGENTS.md`와 01·02·03 문서를 읽고 기존 미커밋 변경을 보존했다.
- 기존 앱의 날짜 기반 가짜 방문 출석, 인덱스 기반 회원권 만료, 가상 직원, 설정하지 않은 주간 목표를 확인하고 제거했다. 과거 직원 localStorage 값은 삭제하지 않고 읽기를 중단했다.
- Python 전체 80개, Android/auth/desktop JavaScript, Chrome 세션·카메라·녹화·PWA 테스트가 변경 전 통과했다.
- 임시 SQLite DB와 합성 관리자만 사용해 `artifacts/frontend-before/`에 대시보드·회원·센터·직원·출석·설정 1366×768 스크린샷을 확보했다. 실제 사용자 DB는 사용하지 않았다.

## 현재 미리보기 실행

로컬 개발 서버에서 `/preview.html`을 열면 기본 OFF 안내를 표시한다. `/preview.html?enable=1`로 명시적으로 활성화한다. 로그인·기존 앱 스크립트를 로드하지 않는 별도 진입점이며 항상 “개발용 샘플 데이터”를 표시한다. 기존 앱 설정 화면에서 기본 OFF 진입점으로 연결한다.

- 전용 localStorage 키: `boxingcoach.dev.operations.v1` 하나만 사용한다.
- 상단 역할 선택: 합성 관리자·코치·회원. 실제 계정 전환이 아니다.
- 기준일 기본값: `2026-09-18`. 날짜 입력으로 재현 날짜를 바꾼다.
- “샘플 초기화”: 전용 키만 제거. 실제 인증·회원·직원·설정·녹화에 접근하지 않는다.
- “다음 요청 실패 재현”: 다음 서비스 조회 또는 저장이 실패한다. 입력 보존·재시도 확인용이다.
- 저장된 개발용 데이터가 손상되면 자동 덮어쓰지 않고 초기화를 안내한다.

## 현재 구현과 파일

| 파일 | 책임 |
|---|---|
| `web/preview.html` | 명시적 개발용 진입점. 기존 인증과 장치 스크립트를 로드하지 않음 |
| `web/scripts/operations-service.js` | 비동기 개발용 저장소, 입력·관계·역할 검사, 중복 요청 방지, 변경 이력 |
| `web/scripts/operations-ui.js` | 이스케이프, 표, 필드, 배지, 필터·페이지 이동, native dialog와 저장 오류 처리 |
| `web/scripts/operations-commerce.js` | 상품·이용권·출석·수납 목록과 변경 폼 |
| `web/scripts/operations-shell.js` | 미리보기 역할·날짜·탐색, 대시보드·회원 상세·회원 홈·운동 기록 |
| `web/scripts/operations-live.js` | 기존 회원/세션 API 어댑터, 프로필 ID↔계정 ID 매핑, 미연결 변경 차단 |
| `web/scripts/center.js` | 실제 센터 표시, 장치 로컬 정보·라운드 설정, 미연결 직원/출석 안내 |
| `web/styles/operations.css` | 관리 화면 전용 토큰·컴포넌트·반응형 다크/라이트 스타일. 기존 세션 스타일에 적용하지 않음 |

현재 회원 등록·수정·메모, 상품 등록·수정, 이용권 부여·휴회·재개·연장·해지, 방문 등록·취소, 수납 등록·취소·부분/전체 환불 **기록** 서비스가 구현돼 있다. UI의 저장 실패는 입력을 유지한다. 서비스는 같은 요청 ID와 내용에 같은 결과를 돌려주고 다른 내용 재사용을 거부한다. 운동 기록 미리보기는 현재 빈 데이터이며 실제 녹화를 생성하지 않는다.

실제 앱에서는 동일 관리 컴포넌트로 회원 등록·수정, 회원 상세 및 운동 기간/이름/완료 상태/정렬/페이지 이동/녹화 열기를 제공한다. 운영 미연결 저장은 HTTP 요청 전에 오류를 반환한다. 계정 권한 화면에 검색·역할·상태·페이지 이동 및 실패 입력 보존을 추가했다. 프로필은 레이블 있는 제한 폭 폼으로 정리했다. 센터의 허구 매출 그래프·출석 집계를 없앴고, 장치 로컬 정보임을 표시했다. 설정에 개발용 진입점 안내를 추가했다.

`dashboard.js`, `members.js`, `attendance.js`의 이전 렌더링·임의 데이터 코드를 삭제했다. 재사용 날짜·프로필 표시 함수는 `utils.js`로 이동했다. 기존 `styles.css`에서 현재 HTML/JS에 사용처가 없는 선택자 202개를 검토 후 제거했으며, 공통 관리 화면은 별도 `styles/operations.css`를 사용한다. 모바일 내비게이션을 가로 스크롤로 정리하고, 빈 고정 높이 패널을 제거했다. 나머지 CSS 중복·죽은 선택자 감사는 최종 단계에서 다시 확인한다.

PWA 캐시 `boxingcoach-shell-2026-09-18-1`, 웹 버전 0.5.0. 새 관리 JS/CSS와 preview 문서를 캐시에 등록했다. preview 방문이 기존 index 캐시를 덮어쓰던 경로를 분리했고 오프라인 네트워크 갱신 실패를 처리한다. Android의 `assets.srcDirs=['../../web']`, Python worker의 기존 web 디렉터리 번들 경로로 새 자산이 포함되는 구조다. 네이티브 패키지 빌드 성공을 의미하지 않는다.

## 중간 검증

- `node tests/test_operations_service.js`: 기본 OFF, 전용 저장소·초기화, 회원/상품/이용권/방문/수납/메모, 중복 요청, 실패 원자성, 잘못된 날짜·실제 ID 거부, 역할 경계 통과.
- `node tests/test_operations_browser.js`: 실제 폼 등록·수정·휴회·방문·환불 기록, 검색·상세, 저장 실패 입력 보존·재시도, API 호출 0건, 기존 키 보존 통과.
- 관리자·코치·회원 × 1920×1080/1366×768/390×844 × 다크/라이트의 현재 기본 화면 스크린샷과 페이지 가로 넘침 검사 통과. 모바일 그리드의 표 넘침을 발견하고 수정했다. **모든 화면·모달 조합을 검증했다는 의미는 아니다.**
- 실제 WebView2/Android 기기 실행은 아직 검증하지 않았다.
- `node tests/test_operations_live_browser.js`: 임시 SQLite의 실제 API 회원 등록/수정(프로필 ID 매핑 포함), 미연결 상품 저장 HTTP 0건, 개발용 키 미생성, 허구 매출/직원 제거 통과. 실제 앱 관리자 9개 메뉴 × 3해상도 × 2테마 스크린샷과 페이지 넘침 검사 통과.
- 재실행 Python 80개, Android/auth/desktop JS, 신규 서비스·미리보기·실제 연결 브라우저 테스트 통과. 카메라·녹화·세션 회귀 및 운영/미리보기 두 문서의 PWA 오프라인 분리 테스트 통과.

1. 실제 연결의 역할별 권한 표시, 저장 이후 조회 실패 상태, 기록 관리 동선의 추가 감사.

3. 설정·계정·공통 UI 접근성 및 CSS/대형 렌더링 추가 정리.
4. 신규 주요 화면별 빈 목록·검색 없음·로딩·오류·권한 부족·긴 데이터·키보드·포커스·모바일 검증 확대.
5. 실제 연결/개발용/미연결 전체 매트릭스와 백엔드 연결 명세 완성, 기존 테스트 최종 회귀.
