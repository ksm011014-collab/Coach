# 추적 구간 보고서

보고서 v1의 선택 필드 `tracking`은 `gaps`, `total_ms`, `truncated`를 갖는다. 이전 보고서는 이 필드 없이 유효하며, 누락을 공백 0초로 해석하지 않는다. SQLite 기존 JSON 열을 사용하므로 스키마 전환은 없다. Supabase는 추가 마이그레이션 `202609220002_motion_tracking_evidence.sql`을 적용한다.

각 구간은 라운드 시작 기준 정수 밀리초 `start_ms`, `end_ms`와 `reason`만 저장한다. 원본 영상이나 좌표를 추가 저장하지 않는다. 유효하지 않은 관측 이후 최대 250ms는 `unreliable`, 마지막 결과에서 250ms를 넘긴 시간 및 첫 결과 전은 `no_result`다. 시간 경계는 표본 사이의 근사치이며 실제 몸의 상태나 모든 오인식을 증명하지 않는다. 유효한 좌표도 올바른 동작 판정을 보장하지 않는다.

같은 원인의 연속 구간을 합친다. 첫 200구간 이후에는 총시간만 누적하고 `truncated=true`로 표시한다. 총시간은 생략된 구간까지 포함한다. 서버는 시간 범위, 정수, 정렬·비중첩, 원인, 합계와 생략 표시의 일관성을 검사한다. 최초 종료 보고서를 고정하여 저장 재시도가 구간을 늘리지 않는다.

팝업은 총시간과 앞 5구간을 표시하고 일부 표시/생략을 알린다. 외부 코치 인터페이스에는 전체 공백 초만 전달한다. 운동 실패나 자세 오류 횟수로 집계하지 않는다. 단위 검사는 무결과·유효/무효 전환·역순 표본 무시·오래된 결과·200구간 초과·저장 재시도를 포함한다. PostgreSQL 및 staging에서는 저장·재조회·다른 센터 접근 거부를 확인했다. 실제 카메라 정확도 검증과는 별도다.
