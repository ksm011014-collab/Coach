# PostgreSQL 권한 회귀 테스트

`box/tests/rls/`에서 실행한다.

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
```

PGlite 0.5.8의 메모리 PostgreSQL에 저장소의 모든 SQL 마이그레이션을 순서대로 적용한다. 운영·staging URL이나 자격 증명은 사용하지 않는다. `auth.users`, `auth.uid()`, `auth.jwt()`와 Supabase 역할은 테스트용으로 구성하며, 각 요청은 `SET LOCAL ROLE authenticated`로 실행한다. 일반 접근 검사는 롤백하고, 중복 요청 검사는 메모리 DB에 커밋한 뒤 별도 트랜잭션에서 재요청한다. 합성 계정/센터만 사용한다.

현재 검증: 역할별 세션 읽기·생성·종료 권한, 타 센터 계정 연결 거부, 소유권 변경 거부, 코치 라벨과 세션의 센터 일치, 중지 계정 거부, 과거 캘리브레이션 RPC 권한 철회, 신규 마이그레이션 재실행 시 전체 세션 필드 보존.

세션 RPC 검증: 동일 요청 키로 시작 재시도 시 ID/시작 시각 유지, 같은 키의 다른 내용 거부, 종료 재시도 시 첫 종료 시각 유지, 타 센터 종료 거부, 임의 분석 점수 삽입 거부.

토큰 검사: DB에 전달된 검증 완료 클레임을 모사한다. 계정 버전 변경 후 이전 버전 거부, 현재 버전 허용, 누락·형식 오류 거부, 이전 플랫폼 토큰의 관리자 호출 거부, Hook 실행 권한과 서버 값에 의한 클레임 덮어쓰기를 검사한다. JWT 서명 검증과 실제 Auth의 Hook 호출은 staging 검증 대상이다.

가입 트리거 검사: `auth.users` 삽입으로 실제 저장소 트리거를 실행한다. 회원 한도 초과 시 Auth/계정/프로필 전체 롤백, 중지 회원의 정원 포함, 회원 역할 전환 한도, 중지 센터 가입 거부, 타 센터 계정 생성 요청 거부, 정상 요청 소비와 최소 감사 기록, 생성자 버전 변경 후 미사용 요청 거부를 검증한다. PGlite 단일 연결 테스트이므로 동시 연결의 정원 경쟁은 staging PostgreSQL에서 추가 검증해야 한다.

실제 PostgreSQL 권한 검증이며 SQL 문자열 검사가 아니다. 다만 GoTrue 토큰 발급, PostgREST 관계 조회·RPC HTTP 응답, Edge Function과 배포된 Supabase 환경은 실행하지 않는다. 이 통합 검증은 staging에서 별도로 필요하다. 후속 인증·세션 마이그레이션을 구현하면서 테스트 범위도 확장해야 한다.
